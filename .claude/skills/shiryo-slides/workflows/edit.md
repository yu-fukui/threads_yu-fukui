# edit モード手順書

既存の `slides/*.html` に修正指示が来た場合。

このモードの肝は **既存デッキの体裁に合わせること**。作り直すのではなく、いま入っている設計をそのまま延長する。テーマ・用途・見出しの語法・面の使い方は、**すべて既存 HTML 側が正本**として扱う。

---

## フェーズ A: 対象と設定の特定

### A-1. ファイルを特定する

```bash
ls slides/*.html 2>/dev/null
```

1 個ならそれを使う。複数あれば 1 問だけ確認する（「どれを直しますか」＋ファイル名の一覧）。0 個なら edit は成立しないので quick / full へ誘導する。

### A-2. テーマ・用途・スタイルはマーカーコメントから判定する

`<body>` 直後のマーカーが正本（`core/rules.md` §11）。

```html
<!-- kit:slide-zukai-kit v1.1 theme:B use:proposal style:formal viz:low -->
```

`theme:` → `themes/theme-<x>.md` を全文読む。`use:` → `templates/<use>.md` を読む。`style:` → `styles/style-<style>.md` を全文読む（**スタイルの規定はこのファイルが正本**）。**ユーザーに聞き直さない。** マーカーがあるならそれが答え。

マーカーに style / viz があればそれに従う（例: style:visual のデッキに枚を足すときはモチーフ第一候補で設計する）。
旧形式（style なし）は standard / viz:mid として扱い、既存の作りを壊さない。

### A-3. マーカーが無いとき

このキット以前の HTML や、マーカーを消して編集された HTML がある。**まず `:root` の変数値からテーマを推定する。**

| HTML 内の値 | 推定テーマ |
|---|---|
| `--bg:#ffffff` ＋ `--accent:#3d5dc6` | A |
| `--bg:#faf9f5` ＋ `--accent:#d97757` | B |
| `--bg:#F0F4F4` ＋ `--accent:#0D9488` | C |

用途は見出しの語法から推定する。名詞型の見出しに「ご提案内容 / お見積もり / 次のステップ」が並んでいれば提案資料、「結論 / 決めてほしいこと」寄りなら社内向け資料。推定できてもできなくても、**1 問だけ確認する**（返事は待たずに修正へ進んでよい）。

> このデッキはテーマ B（クリーム地・オレンジ）の提案資料として扱います。違っていたら教えてください。

同時に、判定した内容で**マーカーコメントを `<body>` 直後に追記する**（次回の判定を確実にするため）。どのテーマにも当てはまらない配色なら、**テーマを当てはめない。** 既存の変数名と値のまま局所編集し、完了報告に「テーマ判定不能のため既存の配色を踏襲した」と書く。

### A-4. kit バージョンが食い違うとき

マーカーの `kit:slide-zukai-kit v<X>` と、いま読んでいるキットのバージョンが違うことがある。受け取り手は `git pull` で随時更新するため、**作りかけのデッキと新しいルールは日常的に衝突する。**

**原則: 既存デッキの体裁を優先する。**

| やること | やらないこと |
|---|---|
| 指示された箇所だけを直す | 新ルールを全スライドに適用して作り直す |
| 新ルールは**編集した箇所にだけ**適用する | 既存の見出し語法・面の使い方を一括で書き換える |
| 変数名が現行と違っても既存の名前を使い続ける | 現行の語彙にリネームして全置換する |

完了報告に 1 行添える。黙って新旧を混ぜない。

> このデッキは v1.0 で生成されています（style 指定なし＝standard / viz:mid として扱いました）。現行キットとルール差がありますが、既存の体裁を優先して 5 枚目だけ修正しました。

全面適用したい場合は edit ではなく、**ユーザーの合意を取ってから quick / full で作り直す**（フェーズ E）。

## フェーズ B: 指示の解釈とスコープ判定

| 指示 | 扱い |
|---|---|
| N 枚目の文言・色・サイズを変えて | 局所編集 |
| N 枚目をテーブル／図解にして | 局所編集（該当 `.s` を書き直す） |
| N 枚目と M 枚目を入れ替えて | 局所編集 ＋ ページ番号の整合 |
| N 枚目を削除して／1 枚足して | 局所編集 ＋ ページ番号の整合（全枚） |
| 2 枚以上の追加・全体の流れを変えて | フェーズ E（昇格判定） |

Read するのは `<style>` 定義部と、編集対象の `.s` ＋前後 1 枚で足りる。

---

## フェーズ C: 編集実行

### C-1. 局所編集

該当スライドだけを Edit で書き換える。**触っていないスライドの HTML に手を入れない。**

- 共通 CSS（`.s` の padding、`.pn` の位置、本文サイズ）を変えると全枚に波及する。ここに手を入れたら、部分検証ではなく**全枚撮り直し**に切り替える
- レイアウトを差し替える場合は `core/structure.md` §8 のメタファー集から選ぶ。ただし**前後と同じ体裁を 3 枚連続させない**（`core/rules.md` §3）

### C-2. ページ番号の整合

枚数が変わる編集（追加・削除・分割・統合）では、全 `.pn` の分母（`N / 総数`）を Edit の `replace_all` で一括更新し、各スライドの番号を振り直す。**表紙にも入っているか**を確認する（`core/rules.md` §7）。枚数が変わらない編集ではページ番号に触らない。

### C-3. テーマ整合チェック

編集した箇所に対して実行する。

```bash
# ハードコード色の混入（#fff のみ例外）
grep -nE 'background:\s*#[0-9a-fA-F]{3,8};|color:\s*#[0-9a-fA-F]{3,8};|fill="#[0-9a-fA-F]{3,8}"' slides/*.html | grep -v '#fff'

# 片側カラーボーダー（core/rules.md §1 #1）— background を持つ要素のみ検出（`core/rules.md` §12 の 6 / `core/validation.md` §4-A と同条件）
perl -ne 'while(/<[a-z]+\b[^>]*>/g){ $t=$&;
  if($t=~/border-(left|right|top|bottom):\s*[0-9]+px solid var\(--accent/ && $t=~/background:\s*var\(/){
    print "$ARGV: カードに片側カラーボーダー: ", substr($t,0,90), "\n" } }' slides/*.html

# AI 感装飾・見出しの句点（core/rules.md §1 #5 #6 #7 #17）
grep -nE 'box-shadow|text-shadow|linear-gradient|radial-gradient|animation|transition:|@keyframes|。\s*</h[12]>' slides/*.html
```

加えて、`--accent` を文字色に使っていないか（文字は `--accent-deep`）、面ルールの許容枚数を超えていないか（テーマ定義の値と `core/rules.md` §12-1 で突き合わせる）を見る。提案資料なら `templates/proposal.md` §5 の追加検査を、**編集した枚に対して**実行する。

## フェーズ D: 部分視覚検証（上限 1 周）

範囲は**編集スライド ＋ 前後 1 枚 = 最大 3 枚**。

```bash
# 5 枚目を編集した場合
node "<スキルルート>/scripts/capture.js" "slides/<name>.html" "slides/.work/iter-0" --only=4,5,6
```

観点は `core/validation.md` §4 と同じ。加えて次を見る。

- 前後スライドとの体裁連続性（同じ体裁が 3 枚連続になっていないか）
- ページ番号の分母が正しいか
- 共通 CSS に触れていた場合は**全枚撮り直しに切り替える**（`core/validation.md` §6）

**自動修正は 1 周まで**（iter-0 → iter-1）。残った問題は直さずユーザーに返す。

> 自動修正で解決できなかった点があります。手動で確認してください。
> 該当スクショ: `slides/.work/iter-1/s05.png`

## フェーズ E: スコープが大きくなったときの昇格

次のいずれかに当たったら、edit のまま進めずユーザーに確認する。

- **半数以上のスライドに手が入る**
- 2 枚以上の新規追加、または 3 枚以上の順序入れ替え
- 構成そのものの変更（流れを組み替える・章立てを変える）／テーマの切り替え／kit バージョン差に伴う全面的なルール適用

> これは構成変更のレベルなので、別モードで作り直すほうが安全です。どうしますか。
>  - quick: いまの構成を土台に、変更点を反映して作り直す
>  - full: 構成から設計し直す
>  - edit のまま進める（複数枚の編集として扱う。部分検証しかかけられません）

---

## フェーズ F: 完了報告

- 直したファイルと枚数（`slides/<name>.html` の N 枚目）
- テーマ・用途をどう判定したか（マーカー由来か推定か。推定なら根拠）
- kit バージョン差があった場合はその旨と、既存体裁を優先した判断
- 検証したスクショのパス（`slides/.work/iter-N/`）と、1 周で解決しなかった問題
