# 構成設計 — 判断材料

「何枚にするか」「どういう流れにするか」「1 枚に何を載せるか」「どう見せるか」を決めるための材料。

**このファイルは型のカタログであって、雛形集ではない。**
以下に並ぶ構成の流れもメタファーも、**思いつかないときに引く発想の材料**であって、選んで流し込む先ではない。

---

## 1. 大原則 — 構成は毎回、内容から設計する

> 固定するのはトークン・部品・原則だけ。**ページの骨格は固定しない。**

- **禁止**: このファイルの構成型を 1 つ選び、その並びどおりにスライドを起こすこと
- **禁止**: `templates/` の必須ブロックを上から順に 1 ブロック 1 枚で並べること
- 必須ブロックは**内容要件のチェックリスト**であって、順番・枚数・見せ方を決めるものではない
- `refs/` の HTML は**実装値の実例**であって、骨格の雛形ではない

### 1-1. 設計するときの手順

1. 材料（台本・議事録・メモ・箇条書き）を読み、**言いたいことを 1 文に落とす**
2. その 1 文を成立させるために必要な要素を書き出す（ここで必須ブロックと照合する）
3. 要素ごとに「これは何の形か」を考える — 順序か、対比か、比率か、因果か、サイクルか
4. §6 の表と §8 のメタファー集から**最低 2 候補**を出し、内容に合う方を採る
5. 構成を `slides/<name>-structure.md` に残す。各スライドに**「なぜこの形か」を 1 行**書く

4 の「最低 2 候補」を省くと、ほぼ確実に card grid に落ちる（§6-3）。

## 2. 適正な枚数

固定ではなく、内容密度に応じて ±20% 調整する。**枚数を埋めるために内容を作らない。**

| 場面 | 目安 |
|---|---|
| 社内 — 定例報告・情報共有 | 6〜10 枚 |
| 社内 — 意思決定を求める（選択肢の比較を含む） | 8〜14 枚 |
| 提案 — 初回打診・概要説明 | 8〜12 枚 |
| 提案 — 本提案（費用・体制・スケジュールを含む） | 12〜20 枚 |
| 補足資料（appendix） | 本編の枚数に数えない |

説明時間が示された場合はそちらを優先する。

| 説明時間 | 目安 |
|---|---|
| 5 分 | 5〜8 枚 |
| 10 分 | 10〜14 枚 |
| 20 分 | 16〜22 枚 |
| 30 分 | 20〜28 枚 |

### 2-1. 投影用か、読み物か

**投影して口頭で補う**資料は 1 枚を薄くして枚数で運ぶ。**メール添付で単独で読ませる**資料は枚数を 2 割減らし、1 枚の情報量を上げる（ただし §5 の密度上限は超えない）。判断できないときは投影前提で作り、完了報告でその前提を伝える。

## 3. 構成の型 — 「よく成立する流れ」であって、決まった並びではない

いずれも**内容が要求しない要素は落とし、要求する要素は足す**。表の「崩し方」は、そのまま使ってはいけないことの例示でもある。

### 3-1. 提案資料

| 流れ | 効く場面 | 崩し方の例 |
|---|---|---|
| **課題起点** 現状の課題 → 原因 → 打ち手 → 効果 → 進め方 | 相手が課題を自覚している。RFP への回答 | 原因が 1 つに絞れるなら、原因スライドは打ち手に畳む |
| **結論先出し** 提案の要点 1 枚 → 根拠 → 詳細 → 次の一歩 | 決裁者が同席する。持ち時間が短い | 根拠が数字 1 本なら、その数字だけの 1 枚を作る |
| **比較選択** 選択肢の全体像 → 各案 → 比較 → 推奨 | 相手が複数案・複数社を検討中 | 比較表を先に出し、各案の説明を後ろに回す手もある |

### 3-2. 社内向け資料

| 流れ | 効く場面 | 崩し方の例 |
|---|---|---|
| **判断依頼** 決めてほしいこと → 選択肢 → 各案の帰結 → 推奨 → 期限 | 会議で決を採る | 選択肢が 2 つなら、左右対比の 1 枚に畳む |
| **報告** 結論 → 数字 → 良かった点と課題 → 次の打ち手 | 定例・振り返り | 数字が主役なら、数字のスライドを冒頭に置く |
| **共有・提言** 背景 → 分かったこと → 意味すること → 提案 | 調査結果の共有、改善提案 | 「分かったこと」が 3 つ以上なら 1 つ 1 枚に割る |

### 3-3. 型を疑うサイン

- 表の並びと生成した構成が**完全に一致**した → 内容から設計していない疑いが濃い
- どのスライドも「見出し + 箇条書き 3 つ」になっている → §6 へ戻る
- 材料に無い要素が構成に入っている → 創作している。落とすか TODO ブロックにする

## 4. 各スライドの役割

| 役割 | 果たすこと | よくある失敗 |
|---|---|---|
| 表紙 | 誰に何を提案・報告するか / 日付 / 差出人 | 装飾だけで主題が読み取れない |
| 章扉 | 話が切り替わることを知らせる | 中身のない枚数稼ぎになる |
| 主張 | 1 枚 1 メッセージで結論を言い切る | 主張と根拠を同居させて焦点が消える |
| 根拠 | 数字・事実・事例で主張を支える | 出典のない数字を置く（材料が無ければ TODO ブロック） |
| 対比 | 2 案 / Before・After の差を見せる | 3 つ以上を対比の形に押し込む |
| 手順・段取り | 順序・担当・期間を示す | card grid に入れて順序が消える |
| 詳細・補足 | 聞かれたら答える情報を置く | 本編に混ぜて流れを止める（appendix へ） |
| まとめ | 主張を再掲し、論点を回収する | 目次に戻るだけで結論が無い |
| 次の一歩 | 相手が次にとる具体的な行動と期日 | 「ご検討ください」で終わる |

**面（ダーク面・アクセント面）を役割で決めないこと。** どの面をどこに何枚使えるかは
`themes/<theme>.md` の面ルールが正本で、テーマごとに違う。構成層は面を指定しない。

---

## 4-B. 表紙の型 — 4 つのレパートリー

表紙は毎回ゼロから考えると弱くなるが、固定すると全部同じ顔になる。
**4 つの型を持ち、そのつど内容に合うものを選ぶ。**

| 型 | 骨格 | 効くとき |
|---|---|---|
| **C** ウォーターマーク | 背面に極太の英字を薄く敷く（左右の見切れ可）。前面にタイトル群。**唯一のダーク面** | 主題を英語一語で言い切れるとき。強く印象づけたいとき |
| **E** タイポグリッド | その資料に**実際に出てくる語**を上下に薄く敷き詰め、中央の余白にタイトル | 扱う範囲が広く、中身を一目で伝えたいとき |
| **G** エディトリアル罫線 | 上下に細罫線だけ。中央にラベル・タイトル・サブ。装飾なし | 硬い相手。フォーマルさが要るとき |
| **H** ドット帯 | 上下にドット列を帯として置く。アクセントの濃淡で段階を出す | 軽快に見せたいとき。教材・社内共有 |

### 4-B-1. 選び方と禁止事項

- **テーマと型を固定で紐付けない。** 「テーマ A なら型 G」のような対応表は作らない。テーマは色と字の規定であって、表紙の骨格とは無関係
- **直前に作ったデッキと同じ型を続けない。** 同じ相手・同じシリーズに複数出すときは特に守る
- **型は骨格であって雛形ではない。** 型 E の語は毎回その資料から拾う。型 C の英字は毎回主題から決める。**前のデッキの中身を流用しない**
- 迷ったら **G**。どのテーマ・どの相手でも成立する
- ダーク面を使うのは型 C だけ。**テーマの面ルールで全面ダークが 0 枚のテーマでは、型 C を選べない**（`themes/<theme>.md` を確認する）

### 4-B-2. 型に載せる要素

どの型でも、表紙に置くのは次だけ。**装飾アイコン・図形モチーフは置かない。**

- 英字ラベル（`PROPOSAL` / `INTERNAL` など 1 つ）
- タイトル（1〜2 行）
- サブコピー（任意・1 行）
- 宛名と日付
- 主題を示すチップ（任意・1 つ）

**例外**: デッキの主題そのものを数量で表す図（§8-N のスカイラインなど）は置いてよい。判定は「**その図の寸法に材料由来の根拠があるか**」— 幅・高さが期間比や実数値から決まっているなら内容であり、決まっていないなら装飾なので置かない。この図の中の `--ink-surface` ブロックは図のデータであって、面ルールの「ダークブロック」には数えない（§8-N）。ただしその枚には、それ以外のダークブロックを置かない。

## 5. 1 枚あたりの密度

- **1 スライド 1 メッセージ** — 2 つ言いたいなら 2 枚に割る
- **箇条書きは最大 4 項目** — 5 つ以上は分割するか、図解に変える
- **本文テキストは原則 100 文字以下**（例外: コードブロック・引用）
- **タイトルは 1 行**。やむを得ない場合も 2 行まで
- **数字は単位・期間・出典とセット**で置く。3 点そろわない数字は載せない
- **関係・構造・順序はテキストより図解**（§6）

### 5-1. TODO ブロックがある場合

材料が無い必須ブロックは TODO ブロックとして出す（`templates/<use>.md`）。
**TODO ブロックを含むスライドは、密度が薄いという理由で内容を足してはならない。**
足すことは創作であり、視覚検証でも対象外になる（`core/validation.md`）。

## 6. 図解優先と、card grid 連発の回避

### 6-1. 内容の性質 → 形

card grid（3〜4 列の等幅カード並列）は強力なフォールバックだが、**メタファー検討を飛ばした証拠**でもある。まず下表を引く。

**カード grid・表・箇条書きへの着地基準はスタイルが決める**（正本: `styles/style-<style>.md`）。
visual では最終手段（まず内容の力学 — 進む・積む・交差する・層になる・盛り上がる — を §8 で絵にし、退けた理由を構成ファイルに残す）。
standard では 2 候補検討の上の正当な着地。formal では型と表が正で、モチーフは §8-D / §8-H 系の堅いものに絞る。

| 内容の性質 | 第一候補 | 第二候補 |
|---|---|---|
| 時系列・スケジュール・ロードマップ | 時間軸タイムラインバー（§8-D） | ジャーニー 3-zone（§8-F） |
| 手順・段階・レベルアップ | 縦に積み上がる ladder | 横向き arrow chain（§8-H） |
| 反復・サイクル・検証ループ | 三角ループ図（§8-E） | — |
| 因果連鎖 | 矢印つき 3 カード（原因 → 機序 → 結論） | — |
| 対比（やる / やらない） | 左右 2 カード | — |
| Before / After | 左右 2 カード + 中央矢印 | — |
| 比率・量・構成比 | 横バー / 積み上げバー | — |
| 階層・構成要素 | ピラミッド / 同心円 / ツリー | — |
| 分岐・並列経路の合流 | ブランチ図（SVG） | — |
| 観察対象 + 複数の観点 | デモ画面モック + 注釈（§8-C） | — |
| 持ち物・チェックリスト | 搭乗券 / チケット（§8-B） | ワークシート（§8-A） |
| 記入させる問い・ふりかえり | ワークシート（§8-A） | — |
| 道具・参照物の一覧 | 横並びチップ / タイル | — |
| 進行が障害に当たる・失速 | 壁（§8-I） | 左右対比 + 冬帯 |
| 積み上がって破綻・量の暴走 | 積層スタック（§8-J） | — |
| 交代・逆転・パラダイム転換 | 交差カーブ（§8-K） | Before / After 2 カード |
| 単線の時系列（駅 3〜5 個） | 縦路線図（§8-L） | 時間軸タイムラインバー（§8-D） |
| 世代・時代・バージョンの比較 | 地層断面（§8-M） | 表 |
| 全期間の盛衰・熱量（表紙・全体像） | スカイライン（§8-N） | 時間軸タイムラインバー（§8-D） |
| **等しい重さの並列要素**（上のどれでもない） | card grid | — |

「重要なポイントを文字で列挙したスライド」が続くときは、設計を疑う。

### 6-2. カード幅の決め方（情報の二重符号化を避ける）

カードが等しい重さの並列要素なら `flex:1` で**等幅**にする。幅の比率に意味を持たせたい場合は、上部のタイムラインバー**だけ**で比率を表し、下部の説明カードは等幅にする。比率をバーとカード幅の両方で表すと、狭い側のテキストが潰れて読めなくなる。

### 6-3. 連発チェック

生成後（および構成案の確定時）に確認する。

- [ ] card grid がデッキ全体の **30% を超えていないか**（12 枚なら 4 枚まで）
- [ ] card grid が **3 枚連続していないか**
- [ ] 順序関係・因果関係・時系列のある内容を card grid に押し込んでいないか
- [ ] 直前のスライドと**同じ体裁**が 3 枚以上続いていないか

```bash
grep -cE 'grid-template-columns:repeat\([3-5],1fr\)|display:flex;[^"]*align-items:stretch' slides/*.html
```

ヒットが上の条件に触れたら、**修正ではなく構成設計に戻る**。該当スライドを §6-1 と §8 で置き換えられないか再検討する。

## 7. 短文化

台本や議事録の文章を、スライドに載る形へ圧縮するときの方針。

| やること | やらないこと |
|---|---|
| ですます調 → 体言止め・キーワード化（「Skills という機能があります」→「Skills という機能」） | 数字・固有名詞・専門用語の言い換え |
| 長文 → 1 行のキャッチ + 補足の箇条書きに分解 | 元の意図・ニュアンスの変更 |
| 接続詞・重複表現の削除 | 推測による補足の追加（材料に無いことは書かない） |
| 要になる語を見出しか太字に上げる | 内容のカット・分割の独断（構成の宣言時にユーザーへ伝える） |

## 8. メタファー集

card grid から置き換えて効果が出た型。**各スライドにつき最低 2 候補を検討し、採った理由を構成ファイルに 1 行残す。**

### 8-A. ワークシート / ノート

**使う場面**: 要件整理、記入させる問い、ふりかえり、入力フォームの説明。

- 左端に 6px 程度の縦の綴じ帯を置いて紙面らしさを出す
- 各行は `border-bottom:1px dashed var(--line)` で記入欄にする
- 「Q1」などの短い番号 → 問い → `例:` の記入例を横並びにする
- 記入例は `--dim` + `font-style:italic` で本文より主張を弱める
- ✗ 問いをカード 5 枚に割っただけの grid にする / 空欄の下線だけを並べて何を書くか読めなくする

### 8-B. 搭乗券 / チケット

**使う場面**: 持ち帰り事項、チェックリスト、到達点、次の行動への接続。

- 本体 + 右側 stub の 2 領域。境界に perforated dotted line（`stroke-dasharray="3,4"`）
- 本体は 2×3 の 6 区画にし、各区画に `01 — OUTPUT` のような短いラベルを置く
- 各区画の右上にチェック印（`✓`）。装飾ではなく「持ち帰るもの」の完了印として使う
- stub には次の行動に接続する短い情報だけ（`To:` `期限:` など）
- ✗ チケットの形だけ作って中身は普通の箇条書き / stub に長文を入れる

### 8-C. デモ画面モック + 観察ポイント注釈

**使う場面**: 画面 UI の説明、見てほしい場所の指示、入力 → 操作 → 出力の流れ。

- 中央にターミナル・ブラウザ・エディタなどのモックを大きく置く
- 左右**両側**に番号バッジ付きの観察ポイントを置き、対象へリーダー線を引く
- リーダー線は 40〜120px を目安に。12px 程度の短すぎる線にしない。テキストの bbox を貫通させない
- 注釈本文は 13px 以上。1 注釈 1 メッセージ
- ✗ モック内の 9〜11px のテキストに意味を読ませる / 注釈を片側に詰めて線を交差させる

### 8-D. 時間軸タイムラインバー

**使う場面**: 進行表、ロードマップ、フェーズの流れ、1 日のスケジュール。

- 上段に時間軸と目盛り、中段にフェーズ塗り分けバー（幅は時間比率に合わせる）、下段にタスク注釈
- 強調文は下端のストリップにまとめる。ページ番号の右下セーフエリアは避ける
- 強調語は 1 つの `<text>` 内の `<tspan>` で扱う
- ✗ `text x="..."` を並べて単語単位で位置調整する / バーと下のカードの両方で幅比率を表す（§6-2）

### 8-E. 三角ループ図

**使う場面**: 作る → 動かす → 直す、検証サイクル、反復改善、PDCA 的な流れ。

- 3 ノードを三角配置にし、矢印は `<defs><marker orient="auto">` の `marker-end` で描く。手動 polygon の矢尻は使わない
- 入口 / 出口はループ本体から分離し、外側のボックスとして置く
- 各ノードの説明は三角形の**外側**へ。中心線上や矢印経路上に置かない
- 補助ルールは下端ストリップに分離し、ループ内部に入れない
- ✗ 円形 dashed の枠にノードを押し込む / 矢印の中点に説明を置く / 4 ノード以上を円形に並べる

### 8-F. ジャーニー 3-zone

**使う場面**: Before / During / After、現在 → 移行期 → 到達点、導入前後の変化。

- SVG ではなく **HTML カードの横並び**で実装し、文字を大きく取る
- 番号 36〜48px、見出し 18〜22px、本文 14〜16px を目安に
- 3 区画の面を変え、最後の zone を主役にする（**どの面を使えるかは `themes/<theme>.md` の面ルールに従う**）
- 矢印よりも「横に進む読み順」で流れを出す。区切りだけで足りることが多い
- ✗ 細かい SVG タイムラインにしてラベルを小さくする / 3 zone の情報量をばらつかせる

### 8-G. 避けるべきメタファー

| 避けるもの | 理由 | 代わりに |
|---|---|---|
| 縦書きの回転テキスト | 単純に読みにくい | 横並びチップ、2×4 タイル |
| 円形 dashed の枠 + 内部ラベル | 枠とラベルが干渉し、意味のない装飾に見える | ループなら三角配置、グループなら実線の領域か HTML セクション |
| 矢印の中点に置く説明ラベル | 線が文字を貫通する | 説明はノードの外側へ逃がす |
| 手動 polygon の矢尻 | 向きが path の接線に合わない | SVG の `marker` に統一 |

### 8-H. HTML ピル + テキスト矢印（線描画 SVG の代替）

**使う場面**: 時系列の並び、3〜5 ステップのフロー、双方向の関係、戻り矢印など、「線を引いて要素を繋ぎたい」場面のほぼ全て。

線を引く SVG は「ズレている」「重なっている」と必ず指摘される。**書く前に HTML で代用できないか必ず検討する。**

```html
<div style="display:flex;align-items:stretch;gap:0">
  <div style="flex:1;background:var(--accent-tint);color:var(--ink);padding:14px 18px">STEP 1</div>
  <div style="display:flex;align-items:center;padding:0 14px;
              font-family:var(--ff-en);font-size:30px;color:var(--accent-deep)">→</div>
  <div style="flex:1;background:var(--accent-tint);color:var(--ink);padding:14px 18px">STEP 2</div>
</div>
```

同じ作りで、時系列（`v1 ─ v2 ─ いま`）、双方向（`人 ↔ AI`）、戻り矢印のキャプション（`← 過去に戻せる`）も表せる。使える矢印記号は `→ ← ↑ ↓ ↔ ─`。塗りの上に載せる文字色はテーマの規約に従う（`themes/<theme>.md`）。

| 表現 | 線描画 SVG | HTML ピル + 矢印 |
|---|---|---|
| 直線的な順序（v1 → v2 → v3） | 避ける | 推奨 |
| 同一レーン上の流れ | 避ける | 推奨 |
| 戻り矢印（U 字の曲線） | 避ける | キャプションで代用 |
| branch / merge のグラフ | SVG が適切 | 不可 |
| swimlane 図 | SVG が適切 | 不可 |

### 8-I. 壁（進行 × 障害）

**使う場面**: 勢いよく進んでいたものが限界に当たる話。ブームの失速、施策の頭打ち、制約への衝突。

- 左に進行要素（`--accent-tint` のピル + テキスト矢印 `→`）を 2〜3 本縦に並べ、右に**ズラし積みのブロック壁**を置く
- 壁は幅 120px 前後・1 段 22px・`gap:4px` の 5 段。各段を 2 ブロックに割り、`flex` を 2:3 / 3:2 と交互にして目地をずらす。塗りは `--line`
- 壁の先に「届かなかった対象」を `--dim` で薄く見せる（向こう側があることを伝える）
- 壁のラベルは壁の**上**に置く。壁の中に文字を入れない
- ✗ 壁を 1 枚の大きな矩形にする（質感が出ない）／進行ピルと壁を重ねる

### 8-J. 積層スタック（量の暴走）

**使う場面**: 積み上がって破綻する話。ルールの肥大化、負債の蓄積、手作業の増殖。

- 同じ高さ（20px）・同じ幅（150px 前後）の薄い矩形を `flex-direction:column-reverse` で 5〜6 枚積む。塗りは全枚同じ（`--accent-tint`）。**矩形の中は空にする**（傾けた枚に文字が入ると読めなくなる）
- **上の 2〜3 枚だけ** `transform:translateX(8〜16px)` でズラし、最上段にだけ `rotate(-4deg)` を足して不安定さを出す。上へいくほどズレ幅を大きくする
- `transform` の静的利用は可。`animation` / `transition` は禁止（`core/rules.md` §1 #7）
- スタックの下に一言の注釈（「書いても書いても終わらない」）を `--dim` 12px で置く
- ✗ 全カードを整然と積む（安定して見えて意味が逆転する）／10 枚以上積む／ズラした枚だけ塗りを変える（§1 #22）

### 8-K. 交差カーブ（交代・逆転）

**使う場面**: 旧方式の退場と新方式の台頭。シェア逆転、パラダイム転換。

線描画 SVG は最小化する対象（`core/rules.md` §9）だが、**交差だけは HTML ピルで表せない**。直線 2 本に限って SVG を使う。

- SVG は**直線 2 本だけ**（`stroke-linecap:round`・旧 = `--line` 4px・新 = `--accent` 5px）。交点に `--accent-deep` の circle（r=9 前後）
- **交点 circle は 2 直線の方程式から実交点を計算して置く。目分量で置くと必ずズレる**（実例: 推定座標のまま置いたら viewBox 幅 864 で 26px ズレていた）
- ラベル・年号・説明はすべて HTML の absolute で重ねる（SVG `<text>` は使わない）
- 交点ラベルは**線から 12px 以上**離す。circle との距離ではなく、ラベル外周から 2 本の線への**最短距離を実測**する（円を避けていても線に 0.3px まで寄っていた実例がある）
- ✗ ベジェ曲線で描く（制御不能）／marker 矢じりを付ける（直線の勢いで十分）

### 8-L. 縦路線図（単線の時系列）

**使う場面**: 駅 3〜5 個の単線の歩み。リリース史、キャリア、導入ステップの実績側。

- 左に幅 40px の列を取り、縦帯（`--accent-deep` 6px）+ 駅ドット（20px 正円）。**終点だけ二重丸**（`--bg` 塗り + 5px border の正円）
- 駅間隔は右のテキスト列を実年数比の flex（`3 / 2 / 2` など）で割って取る
- 右に年号（`--ff-en` 800）+ 1〜2 行説明
- **駅ドットの縦位置は `%` ではなく実測に基づく固定 px で年号行に揃える**（実例: `top:9px / 147px / 239px` + `bottom:3px`）。`%` は行の line-height と一致せず最大 21px ズレた。**目視の「ほぼ一致」は信用しない** — ドットと年号の中心 y を実測し、差を 1px 以内にする
- ✗ 横タイムラインの水増しに使う／駅を 6 個以上にする

### 8-M. 地層断面（世代の積み重なり）

**使う場面**: 世代・時代・バージョンの比較。表で並べると時間の重なりが消えるとき。

- 縦に 3 層（**上ほど新しい**）。最上層 = `--accent-tint`、中層 = `--surface`、最下層 = `--bg`。全層に `1px solid var(--line)` の全周 border を置き、上・中層だけ `border-bottom:0` にして継ぎ目を二重線にしない
- 角丸は塊の外周だけ（最上層の上辺・最下層の下辺）。層の間は角丸なしで密着させる
- 各層: 左にキーワード大タイポ（24px）+ 期間ラベル、右に 1 行の説明。**左列は固定幅にして層間で開始位置を揃える。幅は最長ラベルの実測幅 + 余白から決める**（実例: 24px の 5 文字ラベルが実測 228.4px あり、210px 指定では折り返して層内の上下センターが崩れた → 3 層とも 236px に統一）
- 3 層は**すべて別の面**にする（濃淡が時間の深さを表す）。1〜2 層だけ色を変えるのは `core/rules.md` §1 #22 に当たる。preflight 18 はこの型で必ずヒットするので、意図として理由を残す
- 最上層の上に「↑ 現在も継続中」のような接続ラベルを置き、現在に開いた構図にする
- ✗ 4 層以上にする／層ごとに文字量をばらつかせる

### 8-N. スカイライン・熱量バー（全期間の盛衰）

**使う場面**: 表紙・全体像。期間ごとの盛り上がりと沈みを一目で見せる。

- `align-items:flex-end` の flex 行に、**幅 = 期間比・高さ = 盛り上がり**の矩形を 8〜10 本並べる（`gap:3px`・行の高さ 170px 前後）。山の内部は 2〜3 段の段差で上昇を表現する
- 塗りは**状態で決める**（山 = `--accent-deep` / 沈み（冬・停滞）= `--ink-surface` の低いブロック / 現在 = `--accent`）。同じ状態のブロックは必ず同じ塗りにする
- **沈みの `--ink-surface` ブロックは図のデータの一部であり、面ルールの「ダークブロック」（結論／主役を示す 1 要素。テーマ A では「紺ブロック」）には数えない。** ただしスカイラインを置いた枚には、それ以外のダークブロックを置かない
- 文字を載せないので `--accent` の塗りを使ってよい（`--accent` を「文字を載せない図形専用」とするのは `themes/<theme>.md` §1-3 の文字色規約）。**ただしアクセント面の個数制限は別途かかる** — 全 5 テーマで `--accent` 塗りは 1 スライドに 1 箇所まで（同 §2）。山のうち 1 本（＝現在）にだけ使い、残りの山は `--accent-deep` にする
- 角丸は上辺のみ（`var(--radius) var(--radius) 0 0`）。下端をキャンバスに接地させるには、その枚の `.wrap` の `padding-bottom` を 0 にする
- ✗ 高さに根拠のない凸凹を付ける（盛衰の順序と矛盾させない）／バーの中に文字を入れる

### 8-O. 現在地ミニマップ（デッキの背骨）

**使う場面**: 時系列・工程・章立てをデッキ通しで語るとき。中面のヘッダー右に常設し、めくるたびに進む。

- **幅 210px・高さ 16px・`gap:2px`・ラベルなし**（読ませない・位置を示すだけ）。区間は `border-radius:2px`（高さ 16px に `--radius` を当てると丸すぎる。`--radius` 以下なので §1 #8 には触れない）
- 区間の flex 比は、デッキの主図（タイムライン・工程図）と**同一の幾何**を使う。CSS クラスで 1 箇所に定義し、枚ごとに書き換えない
- いま話している区間だけ `--accent`、それ以外は `--line`
- ヘッダーは `justify-content:space-between; align-items:flex-end` で h2 の右に置く。**h2 が長い枚では h2 が折り返す**ので、`<br>` で改行位置を制御するか見出しを短くする（フォントは下げない — `core/rules.md` §5-3）
- 主役スライド（表紙・全体図そのもの・最終回収の枚）には置かない（重複する）
- ✗ ミニマップに文字・目盛りを入れる（文字を入れた瞬間、現在地の表示ではなく進行予告 `core/rules.md` §1 #23 になる）／枚ごとに幾何を変える
